Copies, GPUs and memory: nli_label on 5 × 8 H200

How one labelling run spreads over 5 machines, 40 GPUs and 80 copies, and where each copy keeps its data: CPU + RAM or GPU + GPU memory. Memory sizes are estimates; the real ones come from the sizing run.

One word, five names

A copy is one running python nli_label.py run …. These are all the same thing:

Seen asWhere
one process (one PID)htop, ps, Task Manager
one shard --shard k/80: every 80th file, starting at kthe command line
one log file logs/shard-k.logthe output folder
one line in the Processes listnvidia-smi
one GPU (--device cuda:g), shared with the other copy on that GPUcopy k uses GPU k mod 8

Copies per GPU = 2 → 8 GPUs × 2 = 16 copies per machine → 5 machines × 16 = 80 copies.

1. Five machines: who does which files

Each machine writes its own output folder on its own disk and gives its own report. The machines never talk to each other.

2. Inside one machine: 16 copies, 8 GPUs

Copy k sits above GPU k mod 8: copies 0 and 8 share GPU 0, copies 1 and 9 share GPU 1, and so on. The bars are to scale: at --batch-size 256 two copies use only a small part of an H200's 141 GB, which is why there is room to raise the batch size.

5. Watching GPU, CPU and memory

Ubuntu, 8 × H200

GPU (installed with the driver):

nvidia-smi -l 5          # full table every 5 s
nvidia-smi dmon -s um    # per GPU: use % and memory, every second
nvidia-smi --query-gpu=index,utilization.gpu,memory.used,memory.total \
  --format=csv -l 5
nvidia-smi --query-compute-apps=pid,used_memory --format=csv   # per copy

CPU and RAM (always there):

top                      # press 1: every core; M: sort by memory
free -h -s 5             # RAM every 5 s
vmstat 5                 # CPU, RAM, swap, waiting for disk
ps -C python -o pid,%cpu,rss,args --sort=-rss   # each copy's RAM (rss, KB)
dmesg | tail             # "Killed process" = out of RAM

Nicer screens (need installing; on the offline server bring the packages along):

htop                     # apt: htop
nvtop                    # apt: nvtop, GPU + processes, like htop
iostat -x 5              # apt: sysstat, disk speed
pip install nvitop; nvitop   # GPU, CPU, RAM in one screen

Windows 10, RTX 5090

GPU: nvidia-smi comes with the driver and works in PowerShell the same way:

nvidia-smi -l 5
nvidia-smi --query-gpu=utilization.gpu,memory.used,memory.total `
  --format=csv -l 5

Task Manager (Ctrl+Shift+Esc) → Performance → GPU. PyTorch work does not show in the default "3D" graph: click a graph title and choose Cuda or Compute_0. "Dedicated GPU memory" is the GPU memory (32 GB on a 5090). The CPU and Memory tabs show cores and RAM.

PowerShell counters:

Get-Counter '\Processor(_Total)\% Processor Time' -Continuous
Get-Counter '\Memory\Available MBytes' -SampleInterval 5 -Continuous
Get-Process python | Sort-Object WS -Descending |
  Select-Object Id, CPU, @{n='RAM GB';e={[math]::Round($_.WS/1GB,1)}}

Resource Monitor (resmon): CPU, memory and disk per process.

A 5090 has 32 GB instead of 141 GB: start with 1–2 copies and --batch-size 128–256.
